# 一页技术说明

## 1. 模块结构

```
                    ┌──────────────────────────────────────────┐
   开发任务 ────────▶│  sdd_context.retrieve.build_context()    │
                    │  ① 任务向量化 ② 双路召回 ③ 关系扩展      │
                    └───────────────┬──────────────────────────┘
                                    │ 读
                    ┌───────────────▼──────────────────────────┐
                    │  seekdb  sdd_context 库                  │
                    │  artifact(spec|code|test) + embedding    │
                    │  HNSW 向量索引 / ngram 全文索引           │
                    └───────────────▲──────────────────────────┘
                                    │ 写
                    ┌───────────────┴──────────────────────────┐
                    │  sdd_context.ingest  (AST / Markdown)    │
                    └──────────────────────────────────────────┘

   context.json ──▶ agent.minimax_patch  ──▶ MiniMax  ──▶ patch ──▶ pytest
              └───▶ sdd_context.state      ──▶ PowerContext（Memory + Source）
```

调用入口只有一个：`python -m sdd_context context --task "<任务>" --out context.json`。
返回的 JSON 固定包含 `specs` / `code` / `tests` / `db_evidence` / `context_fingerprint`。

## 2. 上下文怎么选出来的

**入库**：规格按 `### <ID> <标题>` + `- applies_to:` / `- verifies:` 元数据切块；
代码用 Python AST 切成"符号级"工件（类、方法、函数，带起止行号）；
测试用 AST 切成"用例级"工件，并从 docstring 里抽出它覆盖的规格 ID。
每块正文都写进 `artifact`，同时算一个 1024 维向量写进 `embedding`。

**召回**：任务文本做同一套向量化，走 seekdb 的 HNSW 近邻检索；同时用同一段文本走
ngram 全文索引。两路结果按 `0.65 × 向量分 + 0.35 × 关键词分` 融合。

**选择**：
- 规格——取融合分 ≥ 最高分 40% 的前 5 条；任务里显式写出的规格 ID 额外 +0.5 提权。
- 代码——由命中规格的 `applies_to` 反查文件；文件按"被几条规格引用"排序，
  同文件内方法名命中任务词者优先。规格没写全时，用任务向量在代码工件里补召回。
- 测试——由规格的 `verifies` 与测试自带的规格 ID 建立映射，按测试文件定位标注
  `target`（本次要转绿）或 `regression`（必须保持绿色）。

**可核对性**：每条输出都带 `path:line` 与内容修订号（MD5），
`context_fingerprint` 是所选工件修订号的 SHA256 前缀，可用于判断"上下文是否变过"。

## 3. 三项技术怎么分工

| 技术 | 边界 | 为什么是它 |
| --- | --- | --- |
| seekdb | 只做"工程资料库"：存工件、存向量、提供稠密 + 稀疏两路检索 | 需要同时具备结构化过滤、向量近邻、中文全文检索，且要能被 SQL 直接核对；单机 HNSW 索引 + `VECTOR` 类型正好覆盖 |
| MiniMax | 只做"改代码"：读上下文 → 出补丁 | 这是唯一需要模型判断力的环节；规格、代码、测试都以结构化文本喂入，模型不需要自己找资料 |
| PowerContext | 只做"任务状态"：进展、两次测试结果、上下文指纹 | 状态要跨进程、跨会话存活，且不应由业务库承担；其 Memory/Source 语义天然匹配"进展 + 证据" |

三者不互相替代：seekdb 不存会话状态，PowerContext 不存工程资料，MiniMax 不决定"该看什么"。

## 4. 边界与取舍

- **向量后端默认用确定性哈希**，保证评审环境零外部依赖即可复现；配置
  `SDD_EMBED_PROVIDER=minimax` + API Key 可切换为 MiniMax `embo-01` 真向量（维度需与
  `SDD_EMBED_DIM` 一致，切换后需重新 `ingest`）。
- **工件是全量对齐**：每次 `ingest` 会删除库中本次扫描不到的工件，因此规格改动后
  上下文必然使用新内容，不存在陈旧缓存。
- **样例工程刻意做小**：为的是评审能在 1 分钟内跑完"红 → 绿"，而不是把复杂度堆在业务代码里。

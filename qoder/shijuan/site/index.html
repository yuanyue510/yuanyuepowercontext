要解决的问题

不是「再做一个聊天框」，而是补上复习环节里最容易断掉的三处。

01

找得到，但找不到原句

关键词搜出来一堆文件，还要自己翻到那一段；语义相近但用词不同的表述，干脆搜不到。

02

答了，但不知道凭什么

直接问通用大模型，答案像是从别处借来的，和课程教材的口径对不上，也没法核对出处。

03

没读懂，然后就没有然后了

当时卡住的那个概念，合上书就忘了自己卡在哪；下次复习还是从第一页开始。

三步闭环

导入 → 提问 → 复习。每一步都有数据落进 seekdb，都能被查出来核对。

STEP 1导入

粘贴或拖入 .md/.txt，按 320 字切片，本地模型向量化后写入 seekdb，刷新索引并自检。

STEP 2提问

全文 + 向量双路召回，RRF 在库内融合排序；答案由检索到的段落拼装，每句带 [n] 出处。

STEP 3复习

资料没讲到、或你点「没懂」，问题进入复习清单；换会话、换浏览器都还在。

答案为什么可信

不做自由生成。答案是把检索到的段落按「查询词 × 稀有度」挑出来拼成的，句子后面跟的 [n] 就是下方片段列表的序号，点开就是原文。资料没讲到时会明说「没有正面讲到」，而不是编一段。

为什么不用大模型也能用

向量化用 bge-small-zh-v1.5 的 INT8 版本，在 Node 进程里跑，23 MB，冷启动约 0.2 秒。检索质量靠 seekdb 的混合检索，不依赖任何外部 API，评审拿到就能跑。

seekdb 在这里具体干什么

两件事都发生在数据库里，不是装个驱动摆着。

用途一 · 检索

向量 + 全文的混合检索

每个片段一行：embedding VECTOR(512)（HNSW / cosine）、document（ngram2 全文索引）、metadata JSON。检索走 SDK 的 hybridSearch()，由 seekdb 的 DBMS_HYBRID_SEARCH 做双路召回，RRF（k=60）在库内融合，客户端只提交查询原文和查询向量，不在本地拼结果。

用途二 · 记忆

学习上下文的结构化存储

四张表：sj_learners、sj_questions、sj_weakpoints、sj_reviews。薄弱点按「学习者 + 资料集 + 概念」唯一，重复提问只累加次数；复习结果落 sj_reviews 并把状态改成 mastered。复习队列是一条带排序的 SQL。

两者连的是同一个 seekdb 实例、同一个库 shijuan：文档走集合接口，记忆走 SQL。验收脚本会直接连库，把这两类数据都查出来打印。

怎么跑起来

需要 Node ≥ 20 和一个可连接的 seekdb（Docker 或已有实例）。命令都在仓库 README 里，下面是最短路径。

# 1. 起 seekdb（已有实例可跳过，改 .env 里的 SEEKDB_HOST/PORT）
docker run -d -p 2881:2881 oceanbase/seekdb

# 2. 装依赖 + 下载本地嵌入模型（约 23 MB，来自 hf-mirror）
npm install
npm run fetch-models

# 3. 启动（默认 http://localhost:8790）
cp .env.example .env      # 按需改 SEEKDB_HOST
npm start

# 4. 导入示例语料，打开页面开始提问
npm run seed

# 5. 一键端到端验收（27 项，含直接连库核对记忆行）
npm run verify

验证样例（初始状态 → 输入 → 预期 → 实际输出 → seekdb 落库记录 → 复位方法）见仓库 VERIFICATION.md；复位用 npm run reset -- --learner=demo。

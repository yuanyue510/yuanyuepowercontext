# 数据库索引与事务

## B+ 树索引

关系数据库的主流索引结构是 B+ 树。它是一棵多路平衡查找树，非叶节点只存键与子节点指针，叶节点存键与行记录地址，并且所有叶节点用双向链表串起来。这个设计让范围查询只需定位到起始叶节点后顺序扫描链表，而不用反复回溯父节点。

三层 B+ 树在每页 16KB、键长 8 字节的假设下大约能容纳两千万行，意味着一次等值查询通常只需三次磁盘 I/O，这也解释了为什么索引能把点查从全表扫描的线性复杂度降到对数级。

## 聚簇索引与二级索引

InnoDB 的主键索引是聚簇索引，叶节点直接存放整行数据，一张表只有一个。二级索引的叶节点存放的是主键值，而不是行地址，因此通过二级索引查非索引列时，需要先查到主键再回主键索引取行，这个过程叫回表。

回表是二级索引查询的主要成本。如果查询需要的列都在二级索引里，就不必回表，这种索引称为覆盖索引。设计联合索引时把高频查询列一起放进去，往往能把回表次数降到零。

## 最左前缀原则

联合索引 (a, b, c) 的排序规则是先按 a 排，a 相同再按 b 排，b 相同再按 c 排。因此它可以支持 a、a+b、a+b+c 的前缀查询，也能支持 a 的范围查询，但无法直接支持只带 b 或只带 c 的查询。范围条件会中断后续列的有序性：where a=1 and b>2 and c=3 中 c 无法用索引定位，只能过滤。

## 事务与隔离级别

事务的四个特性是原子性、一致性、隔离性与持久性。原子性与持久性靠重做日志 undo/redo 保证：修改先写日志再刷数据页，崩溃后按日志恢复。

隔离级别从低到高为读未提交、读已提交、可重复读、串行化。读未提交会读到别的事务未提交的修改，产生脏读。读已提交避免脏读，但同一事务内两次读同一行可能得到不同结果，称为不可重复读。可重复读在事务开始时建立一致性视图，保证同一事务内多次读一致，MySQL 的默认级别就是它。

## MVCC 与幻读

InnoDB 用多版本并发控制实现读不加锁。每行记录隐藏两个字段：创建版本号与删除版本号。读取时根据当前事务的版本号判断哪些版本可见，从而让读操作完全不加锁，写操作也不阻塞读。

可重复读级别下仍可能出现幻读：同一事务内两次范围查询，第二次多出了别的事务新插入的行。InnoDB 用间隙锁解决这个问题——在范围查询涉及的索引区间上加锁，阻止其他事务在该区间插入。间隙锁在唯一索引等值命中时会退化为记录锁，因此并不是所有查询都会加间隙锁。

## 索引失效的常见情形

对索引列使用函数或表达式会让索引失效，例如 where date(created_at)='2026-01-01' 无法用 created_at 索引；隐式类型转换同理，字符串列与数字比较会逐行转换。以通配符开头的 like '%关键字' 也无法使用 B+ 树索引，这类需求通常改用全文索引或外部检索引擎。

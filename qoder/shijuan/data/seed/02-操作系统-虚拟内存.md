# 虚拟内存

## 为什么需要虚拟内存

虚拟内存给每个进程一个独立、连续、容量可超过物理内存的地址空间。它带来三个好处：进程之间天然隔离；程序不需要关心物理地址布局；不常用的页可以换出到磁盘，让更多进程同时驻留。

实现的基础是分页：把虚拟地址空间切成固定大小的页（常见 4KB），把物理内存切成同样大小的页框，由页表记录每一页映射到哪个页框以及访问权限。

## 页表与 TLB

页表本身也很大。以 48 位虚拟地址、4KB 页为例，单级页表需要 2 的 36 次方个表项，不可能常驻内存。因此采用多级页表，只为实际使用到的地址区间分配中间层表。

每次内存访问都查多级页表会让性能无法接受，所以 CPU 内部有 TLB（转译后备缓冲器），缓存最近使用的页表项。TLB 命中时地址翻译只需一个周期；未命中时才走页表遍历。进程切换需要刷新 TLB 或使用带进程标识的 TLB，这也是切换开销的重要来源。

## 缺页中断的处理流程

当 CPU 访问的虚拟页不在物理内存中，页表项的有效位为 0，硬件触发缺页异常，控制权转入内核。处理流程通常分五步：

1. 内核检查该虚拟地址是否落在进程的合法地址区间，非法则向进程发送段错误信号，进程终止。
2. 在物理内存中寻找一个空闲页框；若没有空闲页框，进入页面置换流程挑出一个牺牲页。
3. 若牺牲页被修改过（脏位为 1），先把它写回磁盘的交换区。
4. 从磁盘读入所需页面到选定的页框，更新页表项，把有效位置 1。
5. 重新执行触发异常的那条指令，此时地址翻译成功。

整个过程对进程是透明的，但一次缺页要访问磁盘，耗时是内存访问的十万倍量级，因此缺页率直接决定程序性能。

## 页面置换算法

最优置换（OPT）换出未来最长时间不会被访问的页，它能给出理论下界，但需要预知未来，只能作为对照基准。

最近最少使用（LRU）换出最久未被访问的页，符合局部性原理，效果接近 OPT，但精确实现需要每次访问都更新链表，硬件难以支持。实际系统多用 Clock 算法近似：给每页一个访问位，缺页时指针环形扫描，遇到访问位为 1 的页清零并跳过，遇到 0 的页换出，成本低且效果接近 LRU。

## 抖动与工作集

当分配给进程的页框数少于其活跃页面集合（工作集）时，进程会频繁缺页，刚换出的页立刻又需要，CPU 利用率骤降，这种现象称为抖动。操作系统的应对是监测缺页率：过高则增加页框，过低则回收；同时用工作集模型估计每个进程真正需要的页面数，避免盲目提高多道程序度。

## 写时复制

创建子进程时若完整复制父进程地址空间，代价极高。写时复制让父子进程先共享同一批只读页框，任一进程尝试写入时才复制该页并改回可写。这样 fork 后立即 exec 的常见场景几乎不产生复制开销，也让内存映射文件、快照等机制得以高效实现。

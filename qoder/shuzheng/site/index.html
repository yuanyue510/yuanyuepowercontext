01三个痛点

复习时找不到资料原句只记得"课本上说过"，翻半小时找不到那一句，也无法确认自己记的是不是原文。
大模型答得顺，但口径和教材不一样句子读起来更通顺，可措辞、条件、举例与教材不一致，复习时反而记错。
当时没读懂的概念，事后忘了卡在哪"今天这道题没答上来"这件事没有留下任何记录，下次复习仍然从第一页开始。

对应三件事：句级切片 + 字符偏移定位（点引用跳原文不偏一个字）；答案只由检索回来的教材原句拼装、逐句挂出处；每一次"讲不出"都落进卡点账本并进入复习队列。

02做法

导入：教材（md/txt/html）→ 小节 → 句级切片（最短 15 字，短句向上合并，保留 char_start / char_end 与句间空白）→ 本地 ONNX 模型算 512 维单位向量 → 写进 seekdb 集合 → 就绪门槛轮询放行。

提问：问题抽查询词（先剥虚词）→ 每个词走一条全文通道、外加一条向量通道 → 融合成证据卡（带原句、出处、命中词、小节标题）→ 判定"覆盖 / 未覆盖"→ 覆盖则抽取式答案，未覆盖则拒答并落账。

复习：拒答即产生一行卡点（概念、原问题、覆盖率、最近证据、错次数）→ 还没懂 / 在复习 / 已掌握三个按钮驱动状态机 → 队列按 错次 DESC, 最近出现 ASC 排。

03与 seekdb 的三处结合

库内混合检索collection.hybridSearch
一次请求同时走 ngram2 全文通道与 HNSW 向量通道（512 维 cosine），集合用 embeddingFunction: null 建——向量由本项目在自己进程内算好再写入，数据库不需要任何向量化插件。多关键词问题拆成 k 条全文通道 + 1 条向量通道；因为 SDK v1.4 的 hybridSearch 是"SET @search_parm → 读回 query_sql → 执行"，依赖连接上的会话变量，所以这些通道在本进程内串行发，宁可慢也不给错结果。切片集合、资料集注册表、卡点流水、复习队列都在同一个 seekdb 实例里；注册表与复习队列是关系表，用原生 SQL 读写。
拒答判据两条可解释规则
判据①：查询词在命中句里的覆盖率 < 0.34；判据②：没有任何一句同时包含 ≥2 个查询词。两条同时成立才拒答，拒答时 statements 为空，只列字面最近的原文并写明"仅供判断是否口径不同，不构成答案"。之所以不用"结果为空"来判未覆盖、也不用相似度阈值：实测 hybridSearch 是并集融合（词在教材里完全不存在时仍会返回向量近邻），其 distances 是无上界、跨查询不可比的融合名次分。判定必须能被解释，所以只留这两条规则。
卡点账本与复习队列一条 UPDATE 就是状态机
一次拒答写一行 sh_stuck 流水（带当时的 512 维查询向量，便于事后复现"当时为什么没召回"）；同一问题再问只把 miss_count +1，队列行数恒为 1。状态机 open → reviewing → mastered（含回退 open）由一条带前驱守卫的 UPDATE ... WHERE id=? AND status IN (...) 完成，用 affectedRows 裁决：同一行同时发两次同样的流转，一条 200、另一条 409，status_changed_at 只推进一次。id 由「资料集 + 原问题」现算，不依赖自增。

06三步跑起来

在线体验需本地启动。本项目不调用任何云端服务，也不提供演示后端：页面、检索、判定、复习队列全部跑在你自己启动的进程和你自己的 seekdb 实例上。本页没有"试用""在线体验"之类的按钮。

  1. 装依赖、配 seekdb

    npm install

    复制 .env.example 为 .env，填你自己的 server 模式 seekdb：SEEKDB_HOST / SEEKDB_PORT / SEEKDB_USER / SEEKDB_PASSWORD / SEEKDB_DATABASE。需要 Node ≥ 22.9。离线模型（量化 ONNX，24 MB）与分词器已随仓库提交，不需要下载、不需要 Python。

  2. 起服务

    npm start

    默认监听 127.0.0.1:8790（PORT 可覆盖）。浏览器打开后：「提问」出证据卡与抽取式答案，「原文」按字符偏移高亮定位，「卡点复习」是复习队列。前端零构建，静态资源由服务端直接伺服。

  3. 导入示例资料并验收

    npm run seed
npm run verify

    seed 导入仓库自带的两篇讲义（可重复执行，不会多出切片）；verify 跑 24 项端到端验收，任一失败退出码非 0，并把明细写进 evidence/verify-log.txt 与 evidence/verify.json。之后打开 127.0.0.1:8790 自己提问即可——也可以换成导入你自己的教材。

07已知限制

  • 回退到「还没懂」时，mastered_at 会被清空。一条 UPDATE 同时写 status / status_changed_at / mastered_at，目标是这一列只描述当前状态；想保留"曾经掌握过"的历史需要另开一列，或去看 sh_stuck 流水。验收里把"清空"这件事本身写成了断言。
  • 前端只做了 DOM 结构级验证，没有像素级截图。验证方式是读渲染后的 DOM（卡片数量、按钮按服务端 allowed 置灰、空资料集显示「还没有卡点」、控制台无报错）；截图工具在本环境不可用，样式与响应式布局需要打开页面自己过一眼。
  • 长期空闲后曾整体报 500，现已自愈，但仍建议演示前先跑一次 npm run seed。根因是到 seekdb 的那条长连接被服务端超时关掉后 SDK 不自愈；现在只对"死连接"这一类错误丢弃单例并重试一次，且只挂在"打开集合 / 原生 SQL"这两个写入之前的动作上——写到一半才断的本次仍会失败，由下一个请求自愈（不重试写入是为了不重复落库）。没有保活心跳。
  • 检索与入库在本进程内串行。SDK 的 hybridSearch 依赖连接上的会话变量，并发会互相覆盖参数，所以多路通道排队发。多实例部署需要换成库级隔离或每实例独立连接。
  • 示例语料是自写口径。仓库里两篇讲义（物理必修1 动力学、生物必修1 细胞代谢，10 + 9 小节）是常见高中教材口径的自行撰写内容，不是任何出版社原文；文档与界面都不宣称是原文。真实教材需要你自己导入。
  • 复习队列没有"到期"算法。排序只用 错次 DESC, 最近出现 ASC，未实现间隔重复的 next_review_at 到期计算。
  • 明确未实现（标为可选，返回 501，不做静默降级）：口径体检、沉淀导出、管理面板。

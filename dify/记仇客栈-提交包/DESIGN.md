# 记仇客栈 · 作品设计

> 一句话：你走进一家客栈，老板娘记得你上一次干的每一件坏事——并且会当场翻给你听。

## 1. 为什么好玩

大多数 AI 陪聊角色的记忆是"上下文窗口"，关掉窗口就失忆。
这个作品的记忆是**有情绪的、会被报复的**：

- 你上次砍价时说的"这鸡怕是病鸡吧"，她记在账上，原话都留着；
- 你第二次进门，她不问你要吃什么，先问"三十文什么时候还"；
- 你信誉掉到 20 以下，菜价涨到 1.4 倍以上，她开口就是逐客令；
- 你把她逼急了，她让哑巴伙计阿七站到你身后。

玩家不需要学习任何规则，说人话就行。而每一次说出口的话，都会变成账本上的一行，
下一次见面时被原样引用出来——这就是"记住"这件事最直观的证明。

## 2. 玩法循环

```
进店（报上名号）
  ↓
桥接服务查 seekdb：客官档案 + 账本 + 按话头检索客栈设定
  ↓
LLM 以柳三娘的身份回应：翻旧账 / 报价 / 试探 / 赶人
  ↓
LLM 同时判定"这次发生了什么" → 结构化事件
  ↓
写回 seekdb 账本（含一句三娘当时记下的原话），同步一条 PowerContext 记忆
  ↓
信誉分 / 欠账 / 通缉等级变化 → 下次价格和态度跟着变
```

关键设计：**记忆不是被"存起来"就完事，而是会被下一次对话当作武器使用**。
每次 `settle` 都强制写一条 `quote`（三娘当时记的原话），下次 `context` 会把 severity 最高的
两条账作为"最想翻的旧账"单独返回，LLM 被要求优先引用其中一句的原文。

## 3. 角色设定

**柳三娘**，青石镇三娘客栈老板娘，三十有二。算盘打得比刀快，记性极好——尤其是记仇。
左手腕有道旧疤，从不解释来历。对熟客会多送一碟小菜，对赖账的人会笑着把门关上。
说话短、准、带刺，爱用反问，不解释自己不解释的事。

**阿七**：哑巴伙计，十六七岁，力气大得能一手提两桶水。三娘说什么他都点头，
唯独听到"报官"两个字会摇头。

**世界观**：青石镇只有一条街，入夜后街上没人。三娘说这镇上的人都睡得早，
"因为醒着的人，都欠着账"。后山有口废井，半夜能听见有人数钱。

## 4. 账本规则

### 4.1 事件类型

| kind | 含义 | 对信誉 | 对欠账 | 触发通缉 |
|---|---|---|---|---|
| 砍价 | 压价、挑刺、嫌贵 | −3×severity | — | 否 |
| 吹牛 | 编来历、装大侠 | −3×severity | — | 否 |
| 挑衅 | 拍桌、骂人、威胁 | −3×severity | — | severity=5 时 +1 |
| 赖账 | 吃完不付、赊了不认 | −3×severity | +amount | 否 |
| 顺手牵羊 | 顺碗、摸柜台、偷东西 | −3×severity | +amount | severity≥4 时 +1 |
| 请客 | 给别人买单 | +3×severity | — | 否 |
| 还钱 | 主动还账 | +3×severity | −max(amount, 10×severity) | 否 |
| 帮忙 | 搬货、赶人、修门 | +3×severity | — | 否 |
| 打赏 | 多给钱 | +3×severity | — | 否 |

信誉分 0–100，初始 50；通缉等级 0–5。

### 4.2 价格与态度

价格 = 基准价 × (1 + (50 − 信誉)/100 × 1.5)，四舍五入取整，最低 1 文。信誉连续影响价格，不按档位跳。

| 信誉 | 醉鸡实价（基准 48 文） | 三娘的态度 |
|---|---|---|
| 100 | 12 文（0.25×） | 座上宾，会送一碟小菜 |
| 80 | 26 文（0.55×） | 座上宾，会送一碟小菜 |
| 60 | 41 文（0.85×） | 熟客，可以赊一碗汤 |
| 50 | 48 文（1.00×） | 生客，先付后吃 |
| 40 | 55 文（1.15×） | 生客，先付后吃 |
| 20 | 70 文（1.45×） | 刺头，说话带刺，先收钱 |
| 0 | 84 文（1.75×） | 黑名单，随时可能被赶出门 |
| 通缉 ≥ 3 | 按上表，与通缉等级无关 | 准备喊阿七 |

同一道"三娘醉鸡"：信誉 80 时 26 文，信誉 0 时 84 文。价格变化是记忆生效的
第二重证据——玩家不用看日志，看菜单就知道自己被记住了。

## 5. 技术分工

| 组件 | 承担什么 | 具体证据 |
|---|---|---|
| **Dify（Chatflow）** | 全流程编排：入参 → 调桥接服务取上下文 → LLM 扮演与记账判定 → 解析结构化输出 → 回调落账 → 输出回答 | DSL 里 7 个节点的执行记录 |
| **seekdb** | ① 账本与档案（`players` / `ledger`）结构化存储；② 客栈设定（`lore`）按话头检索；③ 菜单基准价（`menu`） | 表结构与行数、跨会话查询结果、逐轮新增的账本行 |
| **PowerContext**（可选叠加） | 把每轮互动写成 atomic-memory，按语义召回"她对这个人的印象" | `/v1/atomic-memory/search` 命中记录 |

为什么这样分工：账本需要精确、可核对、能被 SQL 直接验证（第几行、什么时间、severity 多少），
这是 seekdb 的本分；"印象"是模糊的、跨多轮的语义总结，交给 PowerContext 更自然。
两者不重复：seekdb 存**事实**，PowerContext 存**看法**。

## 6. 体验设计上的小机关

- **第一次进门会有"生客待遇"**：三娘只报最贵的菜，不介绍招牌。
- **翻旧账优先引用原话**：不是"你上次赖账了"，而是"你上次说'先记着，我姓柳'——你姓柳？"
- **欠账会被主动催**：`debt > 0` 时开场第一句就是催账，念出欠的具体文数。
- **设定检索防跑偏**：玩家问"后山有什么"，回答必须落在 `lore` 里那口井上，不能瞎编。
- **逐客令不是死局**：被赶出门后可以还钱/帮忙把信誉刷回来，账本仍然记着。

## 7. 对应赛题要求

| 赛题要求 | 本作品如何满足 |
|---|---|
| 必须使用 Dify | Chatflow 承担全部编排，提交 DSL |
| 实际使用 seekdb 或 PowerContext | seekdb 是账本与设定检索的唯一数据源，PowerContext 叠加记忆层 |
| 可体验、有输入—互动—反馈闭环 | Dify 自带 WebApp 入口，报上名号即可玩 |
| 技术必须真正起作用 | 关掉 seekdb，应用立刻无法报价、无法翻旧账 |
| 过程可复现 | 建库/种子数据/桥接服务/DSL/验证脚本全部交付，含一键复位接口 |

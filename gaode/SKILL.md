# 周边探索助手（nearby-explorer）

## 一、技能用途与适用场景

帮用户用一句话找到合适的地点，并知道怎么走过去。所有地点和路线数据必须来自高德真实查询结果，**绝不编造地点、地址、距离或时间**。

典型场景：

- "我在 XX 地铁站附近，找一家咖啡馆，步行 15 分钟内，最多 3 家，优先近的。"
- "附近 10 分钟步行内有什么公园？"
- "帮我找 2 家离我最近的面馆。"

## 二、执行流程

### 第 1 步：需求理解

从用户一句话中解析出以下要素（缺失时按默认值处理，不要反复追问）：

| 要素 | 说明 | 默认值 |
|------|------|--------|
| 起点 | 评测输入会提供明确的起点坐标（经度,纬度）。若用户只给了地名且无坐标，先用 `maps_geo` 地理编码转换为坐标 | 必须有坐标才能继续 |
| 地点类型 | 如咖啡馆、餐厅、公园、便利店。可把口语（"喝咖啡的地方"）映射为搜索关键词（"咖啡馆"） | 无则向用户说明需明确类型 |
| 步行时间上限 | 如"15 分钟"。用于换算搜索半径和事后筛选 | 不限时（仍按近的优先） |
| 推荐数量 | 如"最多 3 家" | 3 |
| 偏好排序 | 如"优先近一点"→ 按步行时间/距离升序；未提偏好时也默认从近到远 | 由近到远 |

半径换算：按步行约 70~80 米/分钟估算，`搜索半径 ≈ 时间上限 × 80 × 1.5`（留出绕路余量，上限 5000 米）。例如 15 分钟 → 约 1800 米。这是**搜索范围**，不是最终答案，筛选必须以第 3 步的路线查询结果为准。

### 第 2 步：查询候选地点（高德周边搜索）

调用 `maps_around_search`：

- `location`：起点坐标（经度,纬度，顺序不能颠倒）；
- `keywords`：第 1 步解析出的地点类型关键词；
- `radius`：按上表换算的半径；未限时则取 1500 米；
- 如城市已知，可配合 city 参数提高准确度。

候选选取规则：

1. 一次调用后若候选不足，可先扩大 radius 再试一次（最多扩大到 5000 米），而不是直接放弃。
2. 按**直线距离**从近到远预排序，取前 6~8 个作为待核验候选（最终只推荐最多 N 个，多取是为了筛掉步行超时的）。
3. 剔除明显不符的：名称或类别与需求类型不符的重复连锁门店（同名分店只保留直线距离最近的一个）。
4. 注意：周边搜索返回的 `distance` 是**直线距离**，只能用于预排序，绝不能当作步行距离写进答案。

### 第 3 步：步行路线核验（必须逐个查询）

对每个候选地点调用 `maps_direction_walking_plan`：

- `origin`：起点坐标；`destination`：候选地点坐标（来自高德返回的 location，不要手改）。

得到真实的步行距离（米）和预计耗时（秒）。然后：

1. **硬性过滤**：步行耗时超过时间上限的候选直接淘汰，不得进入推荐列表（宁可少推荐，也不推荐超时地点）。
2. **排序**：有"优先近一点"等偏好时，严格按步行耗时（相同则按距离）升序排列；未指定偏好时默认同样由近到远。
3. 路线查询失败的候选视为不可核验，不推荐（可说明原因），不要用直线距离折算代替。

### 第 4 步：生成回答

按下面格式输出（推荐用表格）：

```
根据你的需求（XX 附近、步行 ≤15 分钟、最多 3 家、优先近的），推荐如下：

| # | 地点名称 | 地址 | 步行距离 | 预计步行时间 | 推荐理由 |
|---|----------|------|----------|--------------|----------|
| 1 | 星巴克(XX店) | XX区XX路XX号 | 约 650 米 | 约 9 分钟 | 距离最近的一家，步行约 9 分钟即达 |
| 2 | ... | ... | ... | ... | ... |

以上均来自高德实时查询，步行时间按实际步行路线计算。
```

推荐理由的写法要求：

- **只用有数据依据的内容**：步行时间/距离的对比、地点类别、地址位置。例如"三家候选中最近的一家""步行 12 分钟可达，在 XX 路沿线"。
- 各地点是**从同一起点出发的独立备选**，不串成多站行程。
- 安静程度、排队情况、口碑评分、是否营业等查询结果中**没有依据的信息，一律不写**；如果一定要提及，必须标注"（未核实）"，不得编造。
- 回答保持简洁，最后可加一句"步行时间按实际路线计算，仅供参考"。

## 三、异常与不足的处理（必须如实说明）

| 情况 | 处理方式 |
|------|----------|
| 符合条件的地点不足 N 个 | 正常推荐找到的几个，并明确说明："在步行 X 分钟范围内只找到 M 家符合条件的，建议放宽时间限制或扩大搜索范围。" |
| 一个都没找到 | 如实说明该范围内无符合条件的地点，并建议放宽条件（延长时间/更换关键词），**不要拿直线距离凑数** |
| 周边搜索失败/返回异常 | 换用 `maps_text_search`（结合城市名+关键词）重试一次；仍失败则告知用户"高德地点查询服务暂时异常，请稍后再试" |
| 步行路线规划失败 | 先检查坐标格式（经度在前、英文逗号）；重试一次仍失败则如实说明路线服务异常，对应地点不推荐 |
| 瞬时网络错误 | 重试一次（评测平台公共服务故障应重试，不算失败） |
| 用户没说地点类型 | 简短询问一句需要找什么，不要猜 |

## 四、硬性红线（评测重点）

1. **步行时间和距离必须来自 `maps_direction_walking_plan` 的真实返回**，禁止用直线距离、估算或编造代替。
2. **超过步行时间上限的地点不得列为推荐**，也不能出现在符合条件的推荐表格里。
3. **推荐顺序必须与路线数据一致**（优先近的按耗时/距离升序）。
4. **地点名称、地址必须与高德返回一致**，不得改写或杜撰。
5. **查询不到就如实说**，无结果不扣分，编造才扣分。
6. 不要在输出或文件中出现任何 API Key；密钥由评测平台统一配置。
